# 小红书热门笔记查询

使用自带脚本调用红狐 API，按关键词和时间窗返回热门笔记。核心交付是真实数据和原始链接；拓词、HTML、订阅都是可选分支。

## 能力边界

- 数据源：红狐 API，凭证为 `REDFOX_API_KEY`。
- 查询范围：按数据源当前能力处理最近 30 天；“最近”默认近 7 天。
- 数据为入库快照，不等于小红书实时值，也不代表平台官方推荐。
- 评分字段由接口返回，本 Skill 不重算、不补齐。
- 只读取公开数据，不发布、评论、点赞、收藏或绕过登录与风控。

## 输入与默认值

| 输入 | 默认 | 规则 |
| --- | --- | --- |
| 关键词 | 用户原词 | 空字符串表示全站热门 |
| 时间窗 | 近 7 天 | 用户指定时间窗时不得擅自扩大 |
| 数量 | 10 条 | 返回不足时如实交付，不用无关内容补满 |
| 输出 | Markdown 表格 | 用户明确需要文件时再交付 HTML 路径 |

用户说“只查一次”“不订阅”“不要拓词”时，彻底跳过对应分支。

## 工作流

### 1. 提取请求

确认关键词、时间窗、数量和输出形式。已有信息足够时直接执行。

- “穿搭最近什么火” → 直接查“穿搭”，不强制先选细分方向。
- 只有歧义会显著改变结果，或用户明确要做赛道横向研究时，才问一个必要问题。
- 用户要求多方向比较时，最多先确认 3–5 个关键词，分别标注样本和时间窗。

### 2. 预检

```bash
command -v python3
test -n "$REDFOX_API_KEY"
```

- 缺少 `python3` → 停止，说明需要 Python 3；不要自动安装。
- 缺少 `REDFOX_API_KEY` → 停止，提供[红狐 API Key 页面](https://redfox.hk/settings/api-keys?source=skillhub)和配置示例：

```bash
export REDFOX_API_KEY="your_api_key_here"
```

不得打印、回显、记录或提交真实 API Key。

### 3. 计算时间窗

- “最近”“近期” → 从当前日期向前 7 天。
- “近 N 天” → 使用用户给定的 N；超过 30 天时先说明数据源限制。
- “今天” → 说明数据可能尚未入库，询问是否改查最近可用日期。
- 固定日期或固定天数返回 0 条时，不自动扩窗。

### 4. 执行查询

先定位本文件所在目录为 `<skill_dir>`。不要依赖当前工作目录，也不要写死某个 Runtime 的安装路径。

```bash
python3 <skill_dir>/scripts/fetch_xhs_hot_articles.py \
  --keyword "<关键词>" \
  --start-date "<YYYY-MM-DD>" \
  --max-items 10 \
  --page-num 1 \
  --page-size 50 \
  --output-file "<临时或用户指定的绝对路径>.html"
```

当前脚本把 JSON 写到 stdout，并在每次成功查询时写出 HTML。用户未要求文件时，将 HTML 写到 Runtime 的临时目录，不把它作为主交付。

### 5. 验证执行结果

仅当进程退出码为 0 且 stdout 是完整 JSON 时，才进入展示。

检查：

- `keyword` 与请求一致；
- `items` 是数组；
- 每条结果的 `noteLink` 是原始链接；
- 时间和互动字段只引用返回值；
- stderr 的“文件已保存”不能单独作为查询成功证据。

| 触发条件 | 一线处理 | 仍失败时 |
| --- | --- | --- |
| 缺少 Key | 给出配置方式 | 停止，不查询、不编数据 |
| HTTP 401/403 | 说明 Key 无效或无权限 | 停止，不继续消耗请求 |
| 网络超时/5xx | 允许脚本按 `--max-retries` 重试 | 报告原始错误并停止 |
| stdout 不是完整 JSON | 不从日志拼装数据 | 报告格式错误并停止 |
| `items=[]` | 说明该关键词与时间窗返回 0 条 | 等用户选择扩大时间或换词 |

### 6. 交付结果

先写数据口径和实际查询时间窗，再展示结果。

有关键词时：

| 笔记标题 | 作者 | 互动数 | 发布时间 | 相关性 | 热度 | 时效 | 总分 |
| --- | --- | ---: | --- | ---: | ---: | ---: | ---: |
| [返回标题](原始 noteLink) | 作者名 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 |

全站热门时不展示评分列：

| 笔记标题 | 作者 | 互动数 | 发布时间 |
| --- | --- | ---: | --- |
| [返回标题](原始 noteLink) | 作者名 | 返回值 | 返回值 |

交付规则：

- 默认最多展示用户要求的数量。
- 实际不足时写“返回 X 条”，不以 `latestHotArticles` 补满。
- 不把模糊互动数恢复成精确值。
- 不把 `totalScore` 解释成内容质量或账号适配度。
- 用户要求选题分析时，分析与原始数据分区展示，并区分“数据事实”和“推断”。

## 可选分支

### 拓词

仅在用户要求拓词，或结果为 0 且接口确实返回 `relatedSearches` 时展示。

- 优先使用接口返回值，最多 3–5 个。
- 接口没有返回时，可以给语义拓词，但必须标注“语义建议，不是热度数据”。
- 展示后等待用户选择，不自动发起第二次查询。

### 其他热门笔记

`latestHotArticles` 与当前关键词可能无直接关系。只有用户明确要求“再看看其他热门内容”时才单独分区展示，不得混入关键词结果。

### HTML

脚本成功时会生成 HTML。只有用户要求文件时才返回路径；否则只交付 Markdown/JSON 结果。

### 订阅

默认不询问订阅。

用户主动要求定时推送时：

1. 检查当前 Runtime 是否有日历或自动化能力。
2. 展示关键词、频率、执行时间和时区。
3. **🔴 CHECKPOINT · STOP**：等待用户确认后再创建外部任务。
4. 工具不存在时，只说明本次查询可用，不得声称订阅已创建。

## 反例黑名单

- 不因关键词宽泛就强制停止并要求用户选择 10 个方向。
- 不自动扩大用户指定的时间窗。
- 不用 `latestHotArticles` 冒充关键词搜索结果。
- 不从标题、封面或常识补造互动数、作者数据、链接或评分。
- 不把数据源声明写成小红书官方规则。
- 不强推拓词、HTML、订阅或其他服务。
- 不调用当前 Runtime 中不存在的工具。
- 不在失败后输出“查询成功”或生成一张看似有数据的空报告。
