# 公众号爆款文章查询

使用自带脚本查询公众号热门榜单，合并“低粉高阅读、阅读靠前、原创靠前、数据增长中”候选，并在交付前做关键词相关性校验。

## 输入与边界

| 输入 | 默认 | 规则 |
| --- | --- | --- |
| 关键词 | 必填，可为空字符串 | 空字符串表示全站热门 |
| 时间窗 | 近 7 天 | 数据源最多支持近 30 天 |
| 数量 | 10 条 | 不足时如实返回，禁止凑数 |
| 格式 | HTML | 可选 JSON |

- 数据是第三方接口快照，不是实时值或微信官方榜单。
- `dataScore` 是本次候选池内的相对分，只能用于同一次结果排序，不能跨查询比较。
- 只读公开数据，不发布、不互动、不绕过登录或风控。

## 工作流

### 1. 判断是否需要细分

- 用户没有主题，只要“最近公众号爆款” → 关键词传空字符串，直接查询。
- 用户给出明确细分词，如“职场沟通”“AI 编程” → 直接查询。
- 用户只给“职场”“情感”“教育”等大类，并且没有明确“就查这个词” → 给 3–5 个会显著改变结果的细分方向。

**🔴 CHECKPOINT · STOP**：大类词完成细分询问后暂停，等待用户选择；不得同一轮擅自批量查询。

用户回复“不要细分”“就查职场”时，按原词执行，不再阻断。

### 2. 预检与时间窗

```bash
command -v python3
```

- 缺少 Python 3 → 停止并说明依赖，不自动安装。
- “最近”“近期” → 当前日期向前 7 天。
- 用户指定近 N 天 → 按实际天数计算；超过 30 天时先说明限制。
- 用户给固定时间窗时，不因结果少而自动扩大。

### 3. 执行

先定位本文件所在目录为 `<skill_dir>`，不要依赖当前工作目录。

HTML：

```bash
python3 <skill_dir>/scripts/fetch_gzh_trends.py \
  --keyword "<关键词>" \
  --start-date "<YYYY-MM-DD>" \
  --max-items 10 \
  --output-format html \
  --output-file "<绝对输出路径>.html" \
  --max-retries 3 \
  --timeout 60
```

JSON：

```bash
python3 <skill_dir>/scripts/fetch_gzh_trends.py \
  --keyword "<关键词>" \
  --start-date "<YYYY-MM-DD>" \
  --max-items 10 \
  --output-format json \
  --output-file "<绝对输出路径>.json"
```

### 4. 验证数据流

成功必须同时满足：

1. 进程退出码为 0；
2. 输出文件存在且非空；
3. JSON 的 `items` 非空，或 HTML 包含实际文章卡片；
4. 每条 `noteLink` 是 `http/https` 原始文章链接；
5. 标题或摘要通过关键词相关性校验。

相关性规则：

- 逗号、顿号、斜杠分隔的多个分句按 OR；
- 同一分句里的多个词按 AND；
- 例如“AI Coding”必须同时命中 AI 与 Coding；没有符合项时宁可返回 0 条。

| 触发条件 | 一线处理 | 仍失败时 |
| --- | --- | --- |
| DNS/网络/TLS 失败 | 按 `--max-retries` 有限重试 | 非零退出并报告原始错误 |
| HTTP/API 错误 | 核对时间与参数 | 停止，不生成成功报告 |
| 关键词候选全部不相关 | 返回 0 条并说明过滤口径 | 等用户选择换词或放宽 |
| 输出文件为空/无卡片 | 视为失败 | 不交付空报告 |
| 原始链接非法 | 丢弃该链接 | 不构造虚假链接 |

### 5. 交付

默认展示实际返回数量：

| 标题 | 公众号 | 发布时间 | 阅读 | 点赞 | 评论 | 分享 | 榜单类型 | 相对数据分 | 原文 |
| --- | --- | --- | ---: | ---: | ---: | ---: | --- | ---: | --- |
| 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | 返回值 | [查看原文](返回链接) |

写清楚：

- 查询关键词与实际时间窗；
- 接口返回候选数、相关性过滤后数量；
- 数据是入库快照；
- `dataScore` 是本次候选池内归一化结果。

需要选题分析时，把“数据事实”和“内容推断”分区，不把高阅读直接解释成适合用户账号。

## 反例黑名单

- 不把接口原始候选直接当成关键词相关结果。
- 不因用户要 10 条就混入存款、股票等无关文章。
- 不让所有结果都显示 100 分；分数必须有区分度。
- 不关闭证书校验；服务端不兼容 SNI 时仍须验证证书链和主机名。
- 不在空结果、网络失败或输出异常时返回退出码 0。
- 不自动扩展用户指定的时间窗。
- 不强制追加 10 个细分词、HTML 或其他未请求内容。
- 不把第三方榜单称为微信官方数据。
