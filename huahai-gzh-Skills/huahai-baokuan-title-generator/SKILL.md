# 公众号标题工作台

标题要让读者知道“谁发生了什么、为什么值得读”，同时不能比正文证据更确定。

本 Skill 不把“10 万+”当结果承诺，也不引用仓库中不存在的数据集为方法背书。

## 1. 内容与来源台账

从正文、用户说明和外部来源中提取：

| id | 类型 | 内容 | 来源 | 时间 | 状态 |
| --- | --- | --- | --- | --- | --- |
| F1 | 实体 | Codex | 用户文章 | — | confirmed |
| F2 | 成本 | 68 元 | 前后截图 | 实验当日 | confirmed |
| F3 | 结果 | 3 小时降至 20 分钟 | 同一任务对比 | 实验当日 | confirmed-limited |
| H1 | 推测 | 所有人都能复现 | 无 | — | reject |

必须分开：

- 已发生事实、个人观察、引用观点、推测和预测；
- 文章发布时间与事件发生时间；
- 官方声明、媒体转述和作者判断；
- 实体、动作、数字、适用条件和限制；
- 是否真正有亲测过程、独家材料或采访原话。

“来源在正文里出现”不等于来源支持该结论。标题中的关键主张要能回指具体事实 id。

## 2. 选择角度

默认生成 8 个候选，覆盖至少 4 个角度。用户明确要更多时再扩展。

| 角度 | 使用条件 | 骨架 |
| --- | --- | --- |
| 新闻事实 | 事件和时间已确认 | `[实体][已发生动作]：[直接影响]` |
| 实体锚定 | 实体是正文核心 | `[实体]为什么做[动作]` |
| 任务结果 | 有同口径过程证据 | `我用[工具]完成[任务]，变化是[结果]` |
| 数字对比 | 数字来源和口径明确 | `[条件A]到[结果B]：过程与限制` |
| 问题解释 | 正文确实回答问题 | `[现象]为什么发生？` |
| 机制分析 | 有多条证据支持机制 | `[现象]背后的[机制]` |
| 利益影响 | 影响对象和路径明确 | `[事件]会怎样影响[人群]` |
| 观点评论 | 明确是作者判断 | `我为什么认为[观点]` |

冲突、动机、时代判断和情绪表达只能建立在正文证据上。不要为了张力把“合作”写成“开战”，把“可能”写成“正式”。

## 3. 高风险词核验

以下词不是禁词，但必须有对应证据：

| 表达 | 最低证据 |
| --- | --- |
| 刚刚、今天凌晨 | 可核验的事件时间，且对发布时仍准确 |
| 官宣、正式发布 | 官方原始声明 |
| 独家 | 用户实际拥有且未公开的独家材料 |
| 首个、第一、唯一、最大 | 清晰范围、时间和可靠比较来源 |
| 实测、用了 N 天 | 用户真实过程、条件和记录 |
| 禁用、封杀、攻击 | 原始政策/声明或可靠直接证据 |
| 取代、终结、彻底改变 | 正文足以支持的范围；否则改为问题或预测 |
| 偷偷、只为 | 行为和动机均有证据；不能靠想象补动机 |

旧闻不得包装成刚发生，媒体标题不得当成官方原话，预测不得写成已发生。

## 4. 候选审计

每条标题记录：

- `fact_refs`：使用的事实 id；
- `claim_status`：supported / needs_confirmation / reject；
- `angle`：主角度；
- `reader_value`：读者为什么需要点开；
- `risk`：低 / 中 / 高及原因；
- `variant`：相对测试标题改变的唯一变量。

### 直接淘汰

- 正文不能兑现核心承诺；
- 数字、对话、排名、官方结论、体验或独家没有来源；
- 把相关写成因果，或把作者推测写成事件事实；
- 虚构敌意、动机和当事人态度；
- 依靠误解实体关系才成立。

默认不用百分制。按 `兑现度 / 清晰度 / 相关性 / 区分度` 分别标强、中、弱；数据不足时就标不足，不制造精确评分。

## 5. 新闻与时效内容

对新闻、产品发布和政策内容，标题定稿前检查：

1. 原始来源能否打开；
2. `event_at` 与 `published_at` 是否混淆；
3. 事件主体、动作和范围是否准确；
4. 标题是否遗漏关键限制；
5. 二手来源之间是否一致。

无法完成联网核验时，明确写“仅按用户提供材料”，并去掉需要实时确认的强时效词。

## 6. A/B 测试

给 1–2 组，每组只改一个变量：

- 实体前置 vs 读者影响前置；
- 问题句 vs 判断句；
- 数字对比 vs 任务场景；
- 作者观点明示 vs 新闻事实直述。

记录标题、封面、推送时间、用户覆盖、是否二次分发和观察窗口。公众号推送通常不是随机实验；样本和分发条件不同，只能描述表现差异，不能证明标题的单独因果。

## 7. 输出

### 内容简报

- 目标读者：
- 核心实体和动作：
- 已确认事实：F1...Fn
- 推测/缺口：
- 时效状态：已核验 / 仅按用户材料 / 非时效

### 候选矩阵

| # | 标题 | 角度 | fact_refs | claim_status | 风险 |
| --- | --- | --- | --- | --- | --- |

### 推荐

推荐 3 个：稳健首选、读者影响版、单变量测试版。若没有安全可兑现标题，就先列出需补证据，不硬选。

### 淘汰与核验

列出被淘汰标题、原因和需要什么证据才能恢复。

## 8. 改写原标题

1. 标出原标题中的事实、判断和情绪；
2. 保留准确实体和有来源数字；
3. 删除或降级无依据强主张；
4. 给 6–8 个不同角度，而非近义词复制；
5. 明确每版改变的变量。

## 9. 反例黑名单

- 不声称方法来自未随仓库提供、不可复算的“100/1000 篇样本”。
- 不捏造数字、引用、对话、独家、首发、官宣或亲测。
- 不把点击潜力、评分或历史标题模式当阅读量保证。
- 不用标题技巧代替新闻核验。
- 不把预测、相关或单个案例写成普遍事实。
- 不使用污名化、软色情、医疗或收益恐吓博点击。

行为回归见 `test-prompts.json`。
