# 小红书笔记数据复盘

目标是回答三件事：卡在哪一层、证据是什么、下一条只改哪个变量。只分析用户自己的后台数据，不抓取平台数据，不做刷量。

## 边界

- 账号定位和主页承接：转 `huahai-space-xhs-account-audit`。
- 标题改写：转 `huahai-space-xhs-title`。
- 封面只给可验证的信息层级建议，不负责出图。
- 行业经验只能标为“经验假设”；不得写成小红书官方规则。
- 数据不足时可以不给规律，禁止为了显得有用而补结论。

## 先识别输入

### 截图

1. 把可见字段逐项抄成表格；看不清的记“缺失”。
2. 回读关键数字、单位和时间窗，让用户确认后再分析。
3. 只用截图真实提供的维度；没有曝光就不能计算 CTR，没有阅读就不能计算互动率。

### CSV / Excel

先定位本文件所在目录为 `<skill_dir>`，再运行：

```bash
python3 <skill_dir>/scripts/xhs_notes.py probe '<数据文件>'
```

先核对列名映射和时间口径，再计算。不要把全表复制进上下文。

### 口述数字

先算已有指标，再只追问 1–2 个会改变结论的字段。口述值按低置信度处理。

## 数据合同

每次分析都记录：

| 字段 | 必须说明 |
| --- | --- |
| `source` | 截图、CSV、Excel 或用户口述 |
| `captured_at` | 数据截图/导出时间 |
| `time_window` | 发布至今、近 7 天、近 30 天或其他 |
| `note_type` | 图文或视频 |
| `mapping` | 原始列名到规范指标的映射 |
| `validity` | valid、NA 或需要确认及原因 |

不同时间窗、不同笔记形式或推广/自然流量混在一起时先分组；不能直接合并比较。

## 指标与有效性

| 指标 | 公式 |
| --- | --- |
| CTR | 阅读 ÷ 曝光，或平台导出的明确点击率 |
| 互动率 | 赞藏评分享之和 ÷ 阅读 |
| 点赞/收藏/评论/分享率 | 对应互动 ÷ 阅读 |
| 涨粉率 | 涨粉 ÷ 阅读 |
| 藏赞比 | 收藏 ÷ 点赞 |

有效性规则：

- 分母小于等于 0 → `NA`；
- 负数 → `NA`；
- 阅读大于曝光 → CTR `NA`，不得进入分位数或分组；
- 平台 CTR 超出 0–100% → `NA`；
- 平台 CTR 与阅读/曝光计算值明显冲突 → `NA`，让用户确认口径；
- 文件中出现多个时间窗 → 比率全部 `NA`，先拆分时间窗；
- 图文没有完播率、视频没有图文阅读时长时记 `NA`，不能当 0。

平台导出的 CTR 优先保留为 `ctr_explicit`，自行计算值保留为 `ctr_computed`，二者不能静默覆盖。
当前脚本把两者相差超过“1 个百分点或计算值的 20%，取较大者”标为冲突；这是保守质检参数，不是平台口径。原始导出值另保留在 `ctr_raw`。

## 文件工作流

### 1. 探查

```bash
python3 <skill_dir>/scripts/xhs_notes.py probe '<文件>'
```

检查列名、前 5 行、缺失字段、单位和未识别列。映射不确定就暂停询问。

### 2. 计算与质量体检

```bash
python3 <skill_dir>/scripts/xhs_notes.py metrics '<文件>' --out '<绝对输出路径>.csv'
```

成功必须满足：退出码 0、质量提示已读、无效比率已排除、输出文件存在且非空。

### 3. 单维度分组

```bash
python3 <skill_dir>/scripts/xhs_notes.py group '<文件>' --by '选题类型' --metric ctr,collect_rate
```

一次只比较一个维度，并使用组内中位数。判断样本量时看“该组该指标的有效 n”，不是组总行数；有效 n 少于 3 只列样本，不做优劣判断。

## 诊断方法

按漏斗从上到下检查，在第一个有足够证据的异常层停止：

1. 曝光：是否明显低于账号同形式、同时间窗的历史中位数；
2. 点击：CTR 是否明显低于自身基准；
3. 阅读完成：完播率或阅读时长是否低于同形式历史基准；
4. 互动：赞藏评分享结构与自身同类笔记相比哪里缺失；
5. 关注：互动正常但涨粉转化是否持续偏低；
6. 转化：仅在用户有明确私信、购买等目标时评估。

没有至少 10 篇同口径历史时，不假装存在稳定基准。可以提出假设，但必须注明需要怎样继续验证。

不要把 CTR 只归因于标题；它是封面、标题、流量来源和人群匹配的共同结果。不要根据单篇低曝光断言“被限流”。

## 多篇结论强度

| 样本量 | 可做 | 不可做 |
| --- | --- | --- |
| 少于 5 篇 | 逐篇诊断、指出明显差异 | 规律或方向结论 |
| 5–15 篇 | 找极端值、提出假设 | 因果断言、细分过多组 |
| 15–30 篇 | 2–3 组中位数与分位数对比 | 多因素因果归因 |
| 30 篇以上 | 分布、趋势和单变量对比 | 仍不能证明因果 |

默认使用 P25 / 中位数 / P75，平均值只用于说明是否被少数爆款拉高。新旧笔记、图文视频、自然推广数据必须分开。

## 输出

按五段交付：

1. 数据概览：篇数、来源、时间窗、字段映射和质量问题；
2. 漏斗定位：当前最上游异常层及数字证据；
3. 归因：最多 3 条，标记“确定 / 可能 / 待验证”；
4. 规律或假设：附样本量、分组中位数和混杂因素；少于 5 篇省略；
5. 下一步：只给 1–2 个单变量实验，并写清验证指标。

示例：

> 教程组 6 篇的收藏率中位数为 7.1%，测评组 5 篇为 2.3%。这是相关性证据；两组封面形式不同，暂不能把差异归因给选题。下一轮各发 3 篇并统一封面结构验证。

## 失败处理

| 条件 | 处理 |
| --- | --- |
| 缺 pandas | 停止并说明依赖，不自动安装 |
| Excel 缺 openpyxl | 停止并说明只缺 Excel 读取依赖；可让用户另存 CSV |
| 核心列缺失 | 只分析仍可计算的层，其他记 NA |
| 列映射不确定 | 展示候选映射并询问，不猜 |
| 比率冲突或混合时间窗 | 排除统计并请求确认/拆分 |
| 分组样本不足 | 只列样本，不比较 |

## 反例黑名单

- 不把经验 CTR、互动率、完播率或发布时间阈值写成平台规则。
- 不让无效比率进入中位数、分位数或分组。
- 不把缺失字段当 0。
- 不用平均值替代长尾分布。
- 不从单篇或小样本推出内容方向。
- 不预测改完后会达到某个具体数字。
