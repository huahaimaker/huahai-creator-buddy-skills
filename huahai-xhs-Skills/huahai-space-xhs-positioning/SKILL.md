# 小红书定位与验证

定位是待验证假设，不是一次性写出的口号。最终标准是：用户有资格讲、愿意持续讲、目标人群能理解，而且小规模实验出现可复现信号。

已有账号要重新定位时，先用 `huahai-space-xhs-account-audit` 读取主页和历史样本，再决定保留、收窄还是更换方向。

## 1. 建立定位输入表

先收集会改变方案的最小信息。一般一轮问 2–4 个问题；用户要求一次完成时，可基于现有信息输出，但必须标注假设。

### 本人资产

- 经历：真正做过、经历过、能展示过程的事；
- 专业：职业、技能、资质及可公开边界；
- 日常素材：工作、生活、项目会自然产生什么；
- 资源：场地、工具、供应链、人群触达，不包含不可公开信息；
- 表达方式：图文、口播、拍摄、录屏、长文；
- 产能：每周可持续时间和制作成本。

### 目标与约束

- 主目标只能选一个：品牌、商单、销售、私信、求职作品集或个人记录；
- 次目标可选一个；
- 不愿公开什么；
- 是否露脸、是否商业合作、是否有受监管资质；
- 预期验证周期，而非保证结果周期。

### 证据标记

每项写成：

| id | 陈述 | 来源 | 状态 |
| --- | --- | --- | --- |
| P1 | 做 HR 6 年 | 用户原文 | confirmed |
| P2 | 擅长改简历 | 朋友常来咨询 | reported |
| P3 | 每周可投入 4 小时 | 用户估计 | assumption-to-test |

不把“朋友问过”自动升级成市场需求，也不把职业身份自动升级成专业资质。

## 2. 生成候选定位

每个候选必须由四部分组成：

```text
为【具体人群】
在【具体场景】
解决【可观察问题】
凭借【本人真实资产】
```

默认给 2–3 个候选，不为凑数生成 5 个近义版本。

### 粒度检查

候选需要同时通过：

- 用户能在不额外扮演人设的情况下持续讲；
- 目标人群和场景能用一句话说明；
- 能列出至少 5 个不重复的真实题目用于第一轮实验；
- 不依赖未经验证的“蓝海、热门、平台偏爱”；
- 不需要虚构资历、收入、效果或客户案例。

若列不出 5 个真实题目，标为素材不足，不用“必须发 30 篇”逼用户硬撑。

## 3. 外部证据与能力边界

需要看公开样本时，可调用 `huahai-space-xhs-hotspot`。只有返回 `status`、来源、检索时间、时间窗和非空结果时，才把它标为已验证外部样本。

外部样本用于回答：

- 目标问题是否反复出现；
- 哪些内容形式和切入角度正在被使用；
- 样本里有哪些不可迁移条件；
- 哪些空白值得做小实验。

它不能证明：

- 用户一定能获得相同互动；
- 没搜到结果就是“蓝海”；
- 高互动由标题、发布时间或某一因素单独造成；
- 某个账号的身份、团队、投放和资源可以复制。

后端不可用时，把市场证据记为 `unavailable`，用用户访谈和客户端人工搜索补充；不要制造互动数字。

## 4. 候选评估

不要把缺失市场数据塞进一个精确 100 分总分。分别评两条轨：

### 内部匹配

| 维度 | 问题 | 状态 |
| --- | --- | --- |
| 真实资产 | 用户是否确实拥有对应经历/能力 | 强 / 中 / 弱 |
| 续航 | 5–10 个题目是否来自日常素材 | 强 / 中 / 弱 |
| 产能 | 内容形式是否能按周持续 | 强 / 中 / 弱 |
| 目标一致 | 内容是否服务主目标 | 强 / 中 / 弱 |
| 风险 | 是否依赖受监管身份或敏感主张 | 可控 / 待核验 / 不可做 |

### 外部证据

| 维度 | 需要什么 | 状态 |
| --- | --- | --- |
| 问题存在 | 用户问题、搜索样本、评论或咨询记录 | verified / partial / unavailable |
| 形式可行 | 同类样本与用户产能是否匹配 | verified / partial / unavailable |
| 商业路径 | 真实询盘、成交、合作或产品数据 | verified / partial / unavailable |

给推荐时写清：事实、假设、为什么值得测试、什么结果会推翻它。

## 5. 定位句与主页草案

对推荐候选给三项：

1. 一句话定位；
2. 简介草案；
3. 首轮内容边界。

只用 confirmed 或用户同意的 reported 事实。账号名、简介长度、改名影响和导流规则以用户当前客户端和发布时规则为准，不冒充当前平台硬规则。

### 简介骨架

```text
真实身份或视角
持续提供的具体价值
更新范围或互动方式（可选）
```

不写“分享美好生活”“持续输出干货”这类无法区分账号的句子；也不把用户未证实的数字包装成背书。

## 6. 5–10 篇验证实验

第一轮的目标是比较假设，不是追求固定粉丝数。

### 建立实验表

| 字段 | 说明 |
| --- | --- |
| hypothesis | 这篇验证哪个人群/问题/形式 |
| controlled | 保持不变的封面骨架、长度范围、发布时间或投放状态 |
| variable | 本篇唯一主要变量 |
| evidence | 使用哪些真实素材 |
| metrics | 曝光、CTR/阅读、互动、关注等实际可得字段 |
| window | 相同观察窗口 |
| result | 原始值和有效性说明 |

### 推荐排列

- 选择 2 个候选定位；
- 每个候选做 2–4 篇；
- 另留 1–2 篇复测表现较好的角度；
- 一次只改一个主要变量；
- 推广与自然、图文与视频、新旧时间窗分开。

样本少时只报告观察，不下确定因果结论。没有某字段就标 N/A。

### 判断方法

- 用账号自身、同窗口中位数作为临时基线；
- 同一假设至少有一次复测，单条异常不算模型；
- 关注“哪类读者提出了什么具体问题”，不只看点赞；
- 结果相近时优先选择更可持续、成本更低的方向；
- 若所有候选都弱，先检查素材、表达和分发条件，再决定换赛道。

不使用“前 5 篇一定没数据”“30 篇才可判断”“断更两周权重下降”等无来源固定阈值。

## 7. 内容支柱

验证前只给最小内容结构：

- 主问题：直接解决目标人群的高频问题；
- 证据：过程、案例、对比或复盘；
- 人物视角：解释为什么是用户来讲；
- 商业承接：只在主目标需要且有真实产品/服务时设置。

每个支柱先给 2–3 个真实可写题目。无需一次生成“前 20 篇”，除非用户明确要求并且素材足够。

## 8. 分阶段输出

### 阶段 A：盘点

- 已确认资产；
- 主目标和限制；
- 缺失信息与假设。

### 阶段 B：候选

| 候选 | 内部匹配 | 外部证据 | 风险 | 为什么测试 |
| --- | --- | --- | --- | --- |

### 阶段 C：草案

- 定位句；
- 主页简介；
- 内容支柱与边界。

### 阶段 D：实验

- 5–10 篇实验表；
- 采集字段和时间窗；
- 保留、收窄或放弃的预先判断标准。

用户在交互咨询中，每阶段结束设置确认点。用户明确要求一口气输出时可以完成全套，但假设必须显式列出。

## 9. 重新定位

1. 先审计现有主页和多篇数据；
2. 保留已验证的人群、问题、素材与表达；
3. 一次只改定位句、内容支柱或形式中的一个主要变量；
4. 用新一轮同口径数据比较；
5. 不因一条低数据笔记整体重启账号。

## 10. 红线

- 不虚构职业、学历、资质、客户、收入、地点和经历。
- 无专业资质不提供受监管领域的个体诊断或保证。
- 不承诺涨粉、变现、限流或推荐结果。
- 不把公开竞品表现当作用户可复制结果。
- 不批量起号、刷量、绕风控或照搬竞品。
- 不引用仓库中不存在的 Skill。

行为回归见 `test-prompts.json`。
