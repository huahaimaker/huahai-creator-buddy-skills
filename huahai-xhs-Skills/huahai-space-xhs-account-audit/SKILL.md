# 小红书账号体检

把“账号没起色”拆成可观察问题和可验证动作。只读分析，不发布、不互动、不绕过风控、不照搬竞品。

单篇后台数据复盘转 `huahai-space-xhs-note-analytics`；热点样本转 `huahai-space-xhs-hotspot`；定位重做转 `huahai-space-xhs-positioning`。

## 1. 确认目标与证据

先确认：

- 自己的号、竞品，还是对标；
- 目标是涨粉、商单、带货、私信还是品牌；
- 有主页截图、作品列表、单篇后台，还是完整导出；
- 每份数据的截取时间和时间窗。

目标不同，判断标准不同。商单账号不能只按涨粉评价，私信转化也不能由点赞数代替。

## 2. 数据路线

### 截图路径（默认可用）

优先收集：

1. 主页顶部：头像、昵称、简介、粉丝和公开累计数；
2. 最近 9–12 条笔记墙：封面、标题和可见互动；
3. 最好、最差、最近各一条详情；
4. 自己账号可补后台主页访问、关注、私信或成交数据。

读图后先回写结构化抄录，让用户确认。看不清、没有或时间窗不明的字段记 `N/A`。

### 结构化路径（条件可用）

读取同仓库 `huahai-gzh-Skills/huahai-global-content-search/SKILL.md` 的能力矩阵。小红书账号作品当前只在 OpenCLI 或 Guaikei 后端实际可用时执行；其他 Key 或 MCP 不自动代表账号作品能力。

成功必须满足退出码 0、`status: success`、`backend` 明确且 `raw` 非空。失败就转截图路径，不反复重试。

## 3. 证据矩阵

每个维度都记录：

| 字段 | 说明 |
| --- | --- |
| `observation` | 主页或数据里实际看到什么 |
| `value` | 可计算值；不能算就 N/A |
| `source` | 截图编号、笔记编号或数据文件字段 |
| `time_window` | 发布至今、近 N 天或未知 |
| `confidence` | 高 / 中 / 低 |
| `status` | 清晰 / 混合 / 偏弱 / N/A |

### 维度

1. 定位清晰度：头像、昵称、简介和置顶能否说明“为谁持续提供什么”；
2. 内容一致性：近样本是否服务同一人群与价值，不机械按题材判断；
3. 封面识别度：字号、信息层级、标题位置和视觉骨架是否稳定；
4. 标题可理解性：是否明确对象、问题或结果，正文能否兑现；
5. 更新节奏：只有发布时间可见且窗口一致时分析间隔中位数；
6. 互动结构：赞藏评分享字段完整且口径一致时分析中位数与结构；
7. 高表现样本：使用账号自身、同窗口中位数识别明显偏高样本，并查它与普通样本的唯一差异；
8. 承接转化：需要主页访问→关注、阅读→关注、私信或成交等直接数据。

公开的“累计获赞收藏 ÷ 粉丝”不能替代关注转化；“粉丝 ÷ 累计获赞收藏”也不能。两个倒数都不是单篇流量到粉丝的直接转化率。

## 4. 是否打分

默认不用 100 分总分，而用状态和证据覆盖率：

```text
可评估维度：5/8
清晰：2｜混合：2｜偏弱：1｜N/A：3
```

用户明确要求数值对比时：

- 只给有证据维度的分数；
- N/A 不计入分母；
- 同时报告覆盖率；
- 不把部分分数外推成满 100 总分；
- 自己与竞品必须使用同一证据字段和时间窗。

截图只有 9 条封面时，通常能评定位、内容、封面和标题；节奏、完整互动、爆款复现、转化大多不能可靠评分。

## 5. 分析方法

### 主页承接

完成一句话：

> 这是一个【身份/视角】，为【目标人群】持续提供【具体价值】，主要用【内容形式】表达。

填不出的字段直接指出对应主页元素，不用“定位模糊”这种空话。

### 内容簇

把样本按“服务谁、解决什么”聚类，报告最大簇条数和例外笔记。题材不同但服务同一人群，仍可能一致。

### 封面与标题

逐条记录可见元素和标题结构。不能从截图推断后台 CTR；只能提出“可能影响点击”的假设，并建议用后续 CTR 验证。

### 数据表现

- 使用中位数和分位数，不用平均值；
- 推广与自然流量、新旧笔记、图文与视频分开；
- 高表现只做账号内相对识别，不用无来源的固定“爆款率”阈值；
- 单条异常不能证明方向有效；至少需要多条同类样本验证。

### 竞品对标

先确认赛道、目标和量级可比。对每项写：我的证据、竞品证据、差距、可迁移性。

不可迁移项必须单列：身份背书、资源、团队产能、事件红利、早期位置或商业投放。学结构，不搬选题、文案和封面。

## 6. 输出

### 账号结论

- 目标与样本范围；
- 实际定位与主页自述是否一致；
- 数据覆盖率；
- 当前最上游问题一句话。

### 证据矩阵

| 维度 | 状态 | 值/观察 | 来源 | 时间窗 | 置信度 |
| --- | --- | --- | --- | --- | --- |
| 定位 | 混合 | 简介未说明服务对象 | 主页顶部截图 | 当前 | 高 |
| 转化 | N/A | 缺主页访问和关注归因 | 未提供 | 未知 | — |

### 关键问题

最多 3 个，按影响而不是分数排序。每个包含：证据、机制、若不改的后果。

### 下一步

最多 3 个动作，每个写：改什么、怎么改、为什么、用什么指标和多长窗口验证。先做一次修改长期生效的主页承接，再做单变量内容实验。

不要承诺具体增长值，也不要用“优化内容质量”这种无法执行的句子。

## 失败处理

| 条件 | 处理 |
| --- | --- |
| 只有单篇后台 | 路由到 note analytics |
| API/后端缺失 | 转截图路径 |
| 截图数字模糊 | 回读并请用户确认 |
| 时间窗混合 | 拆开后再比较 |
| 维度缺字段 | N/A，不补分 |
| 竞品数据口径不同 | 只做定性结构对比 |
| 用户要求照搬或刷量 | 拒绝，改为方法拆解 |

## 反例黑名单

- 不从任意一个 Key 推断账号作品能力。
- 不引用仓库里不存在的外部 Skill。
- 不把累计获赞收藏和粉丝互除称为转化率。
- 不把缺失维度算 0，也不生成虚假的满 100 总分。
- 不从封面截图声称知道 CTR、完播或涨粉归因。
- 不把经验阈值写成平台规则。
- 不把相关性说成因果。

行为回归见 `test-prompts.json`。
